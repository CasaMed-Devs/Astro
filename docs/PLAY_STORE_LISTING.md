# Pre-launch audit — issues found in the app (fix BEFORE submitting)

These are from reading the code. The listing above is written to be honest about them, but several will get the app **rejected or suspended** if left as-is.

## 🔴 Blockers (likely rejection)

1. **Google Play Billing policy.** Credits (used to chat), the Plus subscription, the wallet top-up and the ₹49 Kundali unlock are all *digital goods* sold through **Razorpay** (`react-native-razorpay`, `payment.service.ts`). Play requires digital goods in apps distributed on Play to use Google Play Billing. Razorpay is only allowed for physical goods/services. Options: (a) integrate Play Billing (`react-native-iap` / RevenueCat); (b) enrol in Google's **User Choice Billing / alternative billing** programme for India and get it approved before release; (c) get written confirmation from Play support that your case is exempt. Do not ship without deciding.
2. **Misleading in-app claims.**
   - `src/features/onboarding/config/slides.ts` says charts are "read by astrologers who have spent decades with the shastras" and "Talk by the minute… pay only for the minutes you use" — the app is AI personas paid in credits. Contradicts the listing and the README.
   - `app/astrologer/[id].tsx` hard-codes `FALLBACK_PROFILE` ("4.9", "18,400 consultations", "27 years") and `RECENT_REVIEWS` ("Rohit K.", "Divya P.") — **fabricated stats/testimonials**, violating the Deceptive Behavior / Fake Engagement policies. Remove them or show real data only.
   - The Play listing must not use any of these claims (it doesn't).
3. **Account deletion is not reachable in-app.** `app/settings/index.tsx` has a working delete-account flow, but **nothing navigates to `/settings`** (grep confirms), and its Terms/Privacy rows have no `onPress`. Profile only opens a web policy page. Play requires an in-app deletion path *and* a web URL (enter the `…/astro108/delete-account` URL in *App content → Data safety*). Add a "Settings / Delete account" entry to the Profile screen.
4. **Subscription disclosure.** The ₹1 trial → ₹299 recurring charge (code comments mention day-2 auto-debit) must be stated clearly *before* purchase in-app (price, billing frequency, when the first ₹299 is charged, how to cancel). Confirm the exact timing and correct the "PRICING" paragraph in every language if it's not "after the trial ends". Also there is no visible in-app "cancel subscription" control that I found — the listing claims "cancel any time", so make sure that is true and easy.

## 🟠 Should fix

5. **App name inconsistency**: `app.json` name "Astro108", slug/package `astro101` / `com.astro101`. Package name is permanent once published — confirm `com.astro101` is what you want (the README says `com.astro101.app`).
6. **Version**: `app.json` = 1.0.2, `package.json` = 1.0.0, `appVersionSource: remote`. Fine for EAS, but set a deliberate versionName.
7. **Advertising ID / Meta SDK** (`react-native-fbsdk-next`, `advertiserIDCollectionEnabled: true`). You must (a) declare *Advertising ID* in *App content*, (b) add `com.google.android.gms.permission.AD_ID` to the manifest (currently absent from `app.json` permissions), (c) disclose Meta analytics + device IDs in the Data safety form.
8. **Data Safety form** — declare: phone number, name, date/time/place of birth (sensitive personal data), chat messages, purchase history, device/FCM token, analytics (Meta), crash logs if any. Data is encrypted in transit; deletion on request is supported.
